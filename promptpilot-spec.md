# AskWise — Product and Engineering Specification

> Historical note: AskWise was originally developed under the working name PromptPilot.

## Product purpose

AskWise improves rough text entered into supported AI chat composers. It provides:

- Instant Simple and Structured rewrites from deterministic local recipes
- Advanced rewrites generated by a bundled on-device WebLLM model
- An on-device Refine chat for follow-up edits
- Intent classification, quality scoring, diffs, placeholders, and local attachments

Supported sites: ChatGPT, Claude, Gemini, Perplexity, DeepSeek, and Microsoft Copilot.

## Architecture

### Tier 1: deterministic local improvement

Tier 1 runs synchronously in the content script:

1. Classify the request into a mode.
2. Select a domain sub-recipe when applicable.
3. Generate Simple, Structured, and template-based Advanced drafts.
4. Score the original and rewritten prompt with a deterministic rubric.

Tier 1 requires no model, network request, account, or API key.

### Tier 2: on-device model

Selecting Advanced sends the redacted prompt to the extension service worker, which delegates
to an offscreen extension document. WebLLM runs in that document via WebGPU.

- Default model: Qwen2.5 3B Instruct
- Model weights/tokenizer/config: downloaded from Hugging Face and cached by the browser
- JavaScript and WebAssembly runtime: packaged inside the extension
- Prompt inference: entirely on-device
- External AI APIs, local model servers, and provider ladders: not supported

If WebGPU is unavailable or the model is not ready, Simple and Structured remain available.
Advanced shows a direct on-device model error rather than silently pretending a template is an
LLM rewrite.

## Advanced rewrite contract

The on-device model must:

- Rewrite the prompt, never answer the underlying task
- Correct spelling, grammar, punctuation, capitalization, and obvious speech-to-text errors
- Preserve facts, intent, code, paths, URLs, identifiers, quoted text, and exact errors
- Add only useful context, constraints, method, output format, acceptance criteria, and checks
- Avoid invented specifics and excessive template scaffolding
- Use at most one concise clarification placeholder when ambiguity could change meaning
- Apply target-specific formatting for ChatGPT, Claude, Gemini, or generic models
- Mention tool capabilities only when useful and actually available
- Never invent hidden tools, skills, tool names, GPT Actions, or slash commands
- Return valid JSON with `structured` and `advanced` fields

## Privacy

- No AskWise backend, account, analytics, telemetry, or advertising
- Prompt text is read only from the active composer when AskWise is used
- Attached files are parsed locally
- Common sensitive patterns are redacted before on-device inference
- Model-download infrastructure receives download requests, not prompt content
- Prompt content is not sent to an external AI provider

The canonical policy is:
https://askwise-privacy.vercel.app/privacy-policy

## Permissions

- `storage`: local settings, templates, and model progress
- `offscreen`: WebGPU/WebLLM inference in a hidden extension document
- Supported chat hosts: inject the widget and access the active composer
- Hugging Face / related CDNs: download non-executable model data

The extension does not request localhost, Anthropic, OpenAI, `<all_urls>`, tabs, cookies,
history, or webRequest permissions.

## Quality gates

- Classifier fixtures must pass the gated accuracy threshold.
- Every recipe must produce non-empty variants.
- Advanced system prompts must require proofreading and prohibit invented slash commands.
- Production builds must package model WASM files and exclude remote-code hosts.
- The Chrome Web Store ZIP must contain `manifest.json` at archive root.

## Release flow
